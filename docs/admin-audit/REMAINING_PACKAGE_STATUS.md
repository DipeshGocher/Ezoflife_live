## Boundaries retained deliberately

- Current online/COD/wallet payment mechanics, advance percentage, cancellation refund path, settlement eligibility and current charge calculation were not redesigned. The payout endpoint still **records an external payment**; it does not initiate a transfer.
- New invoice issuance and exception acknowledgment are explicit admin writes. Reports, exports, health checks, evidence viewing and order inspection do not mutate business records.
- An issued invoice is immutable through the application model, not protected from privileged direct database administration. Order/type uniqueness is awaited before concurrent first issuance. Counter first-upsert races are retried without duplicate sequence values.
- Operational GETs derive current exceptions without writing. The minute scheduler stores observations/resolution. It is disabled under test and can be disabled with `OPERATIONAL_MONITOR=false`; there is no provider-send side effect.
- Reports reject more than 50,000 source orders with an explicit request to narrow the period. Permission snapshots and report datasets still require production volume/index acceptance.
- All new implementation is local. No deployment, production migration, live refund/payout, external notification or irreversible infrastructure change was performed.
